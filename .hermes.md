## Padrão de Chat (Hermes) — subpasta por sessão
Cada chat/sessão deste projeto trabalha em uma subpasta de artefatos próprios do chat (scripts, relatórios, rascunhos). O Hermes cria a pasta automaticamente. Código real do repo continua na raiz. Leia também o `AGENTS.md`/`CLAUDE.md` do repo (regras técnicas).

## Barreiras (cadeado físico)
O plugin project-guard BLOQUEIA (mensagem de erro clara):
1. write_file/patch para fora deste projeto e das raízes permitidas (TEMP, ~/auditorias, ~/backups, HERMES_HOME, worktrees).
2. Terminal: mkdir/redirecionamento de escrita para fora das raízes.
3. execute_code: escrita de arquivo para fora das raízes.
4. Pasta de chat FORA de um projeto (só existe dentro do projeto dono).
Se um bloqueio acontecer: use subpasta do projeto para código, ou ~/auditorias/<tipo>/ para artefatos genéricos. Desligar o cadeado (PROJECT_GUARD_OFF=1) é proibido sem ordem do Joaquim.

## Regra de Ouro (casa do Joaquim)
1. TODO arquivo novo nasce DENTRO do projeto dono — nunca na home.
2. Verdade acima de validação: não sabe → diga; falhou → diga. Nunca "sucesso" fabricado.
3. Diagnóstico antes de patch: leia logs/estado real antes de qualquer fix.
4. Auditorias/relatórios genéricos → `~/auditorias/<tipo>/`.
5. GitHub: nunca commitar segredos.
